# Bringing Koko's status line to Codex CLI

**Recommendation for Codex 0.172.0.** Start with a compact Koko footer using the experimental statusline provider built into the released CLI. Codex can supply the displayed thread's identity, model, run state, context, token totals and account limits. A provider can return colored, styled text without asking users to replace their Codex executable. If preserving the full framed, multiline Koko panel is the requirement, a separate terminal pane offers the closest fit. For users already running the cxstatusline patch, a one-to-three-row ANSI adapter is also feasible. [Official provider guide][guide] · [Released contract][contract] · [cxstatusline output contract][cxout] · [tmux renderer][tmuxrender]

Investigated on November 26, 2026. The provider shipped in 0.171.0. The local CLI reported 0.172.0 and `codex features list` reported `tui_extensions_statusline` as experimental and disabled. The conclusions below come from the released upstream sources and seven pinned project revisions. Live activation, visual fidelity and rendering latency still need interactive verification. [0.171.0 guide][firstguide] · [0.171.0 Python sample][firstsample] · [0.171.0 types][firstcontract]

A skill or plugin bundled alongside a HUD does not determine its rendering transport. [cxstatusline patch][cxout] · [brandonwie patch][brpatch] · [tmux launcher][tmuxbin] · [OpenAI guide][guide]

### cxstatusline

The 0.172.0 patch builds payload v1 from the active widget, including thread ID and title, cwd, model, effort, run state, branch, PR, branch changes, and usage. Context occupancy comes from the last usage report, while input, output and cached input come from the cumulative report. Context and quota percentages use fractions, and quota reset times use RFC 3339. The start time is captured when the widget is constructed. Treat it as a TUI start time when a conversation resumes. The supplied branch-change counts also have a different scope from Koko's session edit counts. [Payload construction][cxpayload] · [Widget initialization][cxinit]

The host coalesces render requests within 200 ms, permits one outstanding request and refreshes eligible account limits at 60-second intervals. It writes JSON to the child, closes stdin, and waits up to one second for output. Successful blocks replace the previous block as a unit. Invalid row counts, blank rows, nonzero exits and timeouts leave the last accepted block available. The managed launchers **overwrite** `CXSTATUSLINE_COMMAND` with their own renderer. A custom integration must invoke the compatible patched executable directly with its renderer selection or arrange launcher support. The manifest explicitly pairs the patch with upstream 0.172.0. [Scheduling][cxtick] · [Output validation][cxout] · [Launchers][cxwrap] · [Compatibility manifest][cxmanifest]

### brandonwie/codex-hud

Its patch introduces `[tui].status_line_command`. It invokes a shell synchronously, injects `CODEX_HUD_MODEL`, `CODEX_HUD_EFFORT`, `CODEX_HUD_SERVICE_TIER` and `CODEX_HUD_ROLLOUT_PATH`, and consumes the first trimmed output line. A failed or empty result falls through to the built-in items. The helper has no explicit command timeout. Its ANSI parser supports basic and indexed foreground colors. Koko's bold, dim and RGB styling would need adaptation. The standalone `--watch`, `--line` and `--json` modes can be used independently of that hook. [Command and ANSI parser][brpatch] · [Fallback][brfallback] · [CLI][brcli]

The Rust collector shells out to Git and reads bounded rollout tails for token and limit events. With an explicit rollout path, it obtains context and tokens only from that file. An explicitly empty or invalid path leaves those fields unavailable. An **absent** path, as can happen when running standalone, permits a latest-files fallback that can select another session. Account quotas are collected across up to 50 files and 1,200 tail lines per file, selected by event timestamp and classified by window duration. These are observations from local logs and may lag an account change. A Koko provider can use the official account snapshot instead of doing this scanning inside each read. [Git][brgit] · [Tail selection and classification][brcollect] · [Isolation branches][brscope]

### fwyc0573/codex-hud

The launcher's split is a separate viewport with its own width, height, input handling and repainting. Normal single-session mode looks for an exported `TMUX_PANE` in Codex shell snapshots and pins the matching thread, choosing the highest snapshot nonce. It can keep an established binding and clears session data when there is no usable binding. The implementation also has a separate multi-session overview. Its broad discovery helpers do not define the single-session binding behavior. This approach depends on local Codex files, their naming conventions and tmux. [Shell-snapshot lookup][tmuxlookup] · [Binding][tmuxbind] · [Overview and main loop][tmuxloop]

The HUD watches the rollout, serializes parse requests, keeps a byte offset and running calls by ID, and resets accumulated state after detected truncation. It derives tools, plan events, compactions and token counts from the rollout and can track child agents. The single-session data path uses `token_count.info` for usage. It does not expose account quota windows through this path. Its redraw loop schedules another pass after one second, rereads local Git/config during collection and skips writing an identical terminal frame. Koko could reuse the parser design if a later activity feature justifies understanding another on-disk format. [Rollout events][tmuxevents] · [Parser state][tmuxparse] · [Activity collector][tmuxagent] · [Collection loop][tmuxloop] · [Frame comparison][tmuxrender]

## Stock Codex provider

Codex discovers an MCP tool via `tools/list` with a statusline entrypoint in `_meta["openai/ui"]`. Rendering happens through `resources/read` on its advertised `ui://` URI. The displayed thread's snapshot arrives under `params._meta["com.openai/codex-statusline-state"]`. The response contains one text resource at that URI, with MIME type `application/json` and a JSON-encoded UI tree. A string displays text and a null root clears the view. After each successful read Codex waits one second. A read has a one-second deadline. An error stops polling until the provider is reselected. [Provider contract and enablement][guide] · [Reader implementation][reader]

For **0.172.0**, the tree supports rows with an explicit gap, optional wrapping and background, styled text, links, bold, italic and underline. The host sanitizes string leaves and strips ANSI controls. It accepts up to 64 KiB of tree JSON, 16 KiB of UTF-8 leaf text, 256 non-null nodes and depth 16. The input has no terminal dimensions. Prefer one compact wrapping row with the most important fields first. Rendering a pre-wrapped box at an assumed width would make terminal resize behavior unreliable. The released contract is the compatibility target for this proposal. [Released types][contract] · [Text sanitization][sanitize] · [Resource bounds][guide]

The selected provider owns the statusline content. Codex 0.172.0 allocates height to both the statusline and hints. Inline mode caps this combined area at two rows. Fullscreen caps it at two to four rows depending on available height, and reserved hints can reduce the provider's share. Size a Koko view for information priority and natural wrapping. [Composer layout][hostheight] · [Provider redraw example][obrigadopr]

### Four implementations of the official interface

**scottlz0310/agent-statusline** is the closest architectural reference. Its stdio MCP server reads the displayed thread's snapshot, maps it to its own data model and composes styled spans. The UI backend coalesces spans and emits typed text properties, with a plain fallback when it would exceed tree limits. Its 120-column default is an internal path-shortening policy. Git runs in a background worker with cache entries per cwd, a three-second freshness window, a maximum of 64 directories and an initial wait of up to 80 ms. The installer backs up settings and records the previous provider for restoration. The manifest declares MIT. [Protocol][scottproto] · [Native UI output][scottui] · [Git cache][scottcache] · [Installer][scottinstall] · [Manifest][scottmanifest]

Its Codex adapter also makes display choices specific to that project. It prefers current context usage in an internal input-token slot, suppresses an output-token field and clamps percentages. Koko should retain three distinct facts: current context occupancy, cumulative noncached input/output and cache totals. A bar can saturate at its visual maximum while the numeric quota label still reports 103%. [Codex adapter][scottadapter] · [Official token calculation][usage] · [Official rate-window semantics][contract]

**TakumiOkayasu/dotfiles#542** is the smallest contract example. Its Python provider reads context and the account's `codex` limit independently, identifies the 300- and 10,080-minute windows in either slot and distinguishes absent, zero and greater-than-100 percentages. It separates extraction, conversion to three display values and construction of a wrapping row with gap 1. The merged PR reports 17 tests, including reads over an open stdio stream. The author explicitly left real Codex, narrow terminals and the one-second host deadline unverified. [Provider][takumi] · [PR and verification scope][takumipr]

**obrigado-dev/client#12** illustrates lifecycle and failure handling. It redraws selected built-in items, classifies branch and hostname as local reads, and explicitly lists PR number, branch changes and task progress as missing from the snapshot. It tracks render state per thread, permits one background render per thread, reuses the last successful result and expires old entries. Its app-specific external renderer runs on first observation and transitions between ready and busy. The PR author reports matching 27 native items in a scratch 0.171.0 host and clipping at three rows in their setup. Provider chaining and restoration are product features of this implementation. [Footer items][obrigadoitems] · [Per-thread rendering][obrigadocache] · [State transitions][obrigadoobserve] · [PR and host observations][obrigadopr]

**ccusage/ccusage#2097** adds an MCP mode alongside the standalone preview. Its protocol module advertises an app-only tool, receives the displayed thread ID, and returns a JSON-encoded text root. Its worker scans local rollouts and calculates estimated session and daily consumption; resource reads return a cached per-thread result or loading text without waiting. Fingerprints include the selected thread, local day, speed policy, paths, sizes and modification times. The PR reports a real official prerelease TUI test with fixture logs; that does not establish a live conversation revert or Koko compatibility. Borrow the separation between protocol, current-thread identity and background enrichment. Keep historical pricing optional: these totals describe recorded consumption, not context occupancy or host-reported charges. The current `run_statusline` still dispatches MCP separately from preview JSON/text output. [Merged PR and validation scope][ccpr] · [Pinned protocol][ccmcp] · [Pinned worker][ccnative] · [Current entry point][ccentry]

A user-supplied Windows 0.171.0 report described reliable separation with explicit row gaps and a background covering the rendered content and gaps. It also described a footer disappearing once, followed by improvement after moving OS queries to the background and restarting. The author reported ten local checks. The cause remains unverified. These observations motivate testing narrow windows, using explicit gaps and keeping optional I/O off the response path. The generated release types independently confirm that the provider receives no footer width. [0.171.0 types][firstcontract]

ContextBolt's November 22 walkthrough documents the author's checks of the native picker, configuration and session command in 0.171.0. The author stopped before building a provider and attributes the provider instructions to OpenAI. It supplies a user's view of the built-in controls. The implementation evidence above comes from the code. [ContextBolt walkthrough](https://contextbolt.com/blog/codex-statusline/)

| Koko field | Source and policy for a first version |
| --- | --- |
| Model, effort, session, status | Map `thread.model`, `thread.id`, `thread.name`, `thread.agent.state` and `thread.workspace.cwd`. Use the displayed thread ID to isolate per-session state. [State types][contract] |
| Context | Use host-reported used percentage, used tokens and window size independently. These can become available at different times. [Usage projection][usage] |
| Input, output and cache | Map `other_input_tokens` to Koko's uncached input, `output_tokens` to output and the cache-read/write counters to their respective fields. `total_input_tokens` already includes the cache categories. Omit the breakdown when the total object is absent. [Usage projection][usage] · [Koko token widget](../../src/ui/components/token-breakdown.ts) |
| Limits and cost | Retain reported percentages and Unix reset seconds. Label 5h/7d by actual window duration where supplied, and distinguish missing observations from zero. Keep USD and credits separate, and only show a currency value when the host supplies it. [Account projection][account] · [Cost projection][usage] |
| Git and worktree | The provider gets a cwd. The Git item names in `config.statusline_items` are selections and carry no branch data. An optional local collector can supply workspace details when the host can access that path. Cache by worktree/cwd, do the work outside the read response, and return partial data when unavailable. Koko's current Git collector is synchronous and its optional Worktrunk call alone allows 1,000 ms. [State types][contract] · [Koko workspace collection](../../src/cli/workspace/read.ts) · [Git](../../src/cli/workspace/git.ts) · [Worktrunk](../../src/cli/workspace/worktrunk.ts) |
| Activity and session history | The snapshot omits a rollout path, tool calls, agents, plan steps, start time and cumulative session edits. Omit these from the first release. Any later enrichment must bind to the displayed thread's exact rollout and degrade cleanly if unavailable, especially on resume or when two sessions share a cwd. [Released types][contract] · [Rollout binding precedent][brscope] |

## Proposed implementation and verification

**Phase 0 — establish host behavior.** During implementation, exercise the official starter in an isolated Codex configuration on 0.171.0 and 0.172.0. Enable **Custom status line**, restart the TUI, select the provider in `/statusline`, inspect actual output during a turn and verify thread switches, narrow windows and terminal resizes. Check the available rows with hints present, quota units and optional data on first read. Test timeout and recovery by reselection. [0.171.0 starter][firstsample] · [Official verification workflow][guide] · [Reader lifecycle][reader]

**Phase 1 — ship a snapshot-only footer.** Add an isolated `integrations/codex` entry point for the persistent MCP process. A pure `mapCodexSnapshot` maps released fields into `AgentSnapshot`. Add `"codex"` to `AgentId`. Move normalized session token totals out of their exclusive home in `ActivityData` so the core can represent real totals with absent tool activity. Migrate the existing callers and keep the Claude, Antigravity and OpenCode rendering contracts covered. The CLI's stdin dispatch remains the entry point for its existing hosts. A user can register this provider on the app-server host through the documented MCP mechanism. [Shared model](../../src/core/model.ts) · [Snapshot](../../src/core/snapshot.ts) · [CLI dispatch](../../src/cli/agents.ts) · [OpenCode panel](../../integrations/opencode/panel.ts) · [Provider registration][guide]

Expose the displayed fields as semantic groups of text and style in `src/ui`. Keep the public ANSI `render` facade for existing consumers. Codex's own backend selects compact groups and maps them to native `row` and `text` nodes with gaps, wrapping and theme colors. Prioritize model/effort, context and available account limits, then run state, reported totals and host-provided cost. Omit absent facts. The current full-panel formatter adds borders and separators and requires a supplied width. A shared content representation preserves the presentation decisions that make sense on both surfaces. [Koko renderer](../../src/ui/render.ts) · [Layout](../../src/ui/lines.ts) · [Existing span conversion](../../integrations/opencode/ansi.ts) · [Native span backend precedent][scottui]

**Phase 2 — enrich and verify.** If workspace information is needed, add local Git only when the provider and workspace are on the same accessible host. Return session fields immediately and refresh workspace data asynchronously, keyed by cwd/worktree with one refresh in flight and a bounded cache. Represent failure as an unavailable workspace section. Keep session facts keyed by thread ID. Follow Koko's enforced dependencies: when the concrete Git collector gains a second consumer, move it to a shared workspace-acquisition module and explicitly classify that module and the new integration in the architecture test. Avoid importing a CLI entry point or private UI compositor into a host integration. Consider rollout-based tools/plans only after the native view is validated and exact thread binding is demonstrated. [Architecture rules](../../tests/architecture.test.ts) · [Workspace acquisition](../../src/cli/workspace/read.ts) · [Cache example][scottcache] · [Per-thread example][obrigadocache]

Check protocol discovery, resource URI/MIME type, tree bounds, cold-cache latency, optional fields and actual zero, missing windows, usage over 100% and cache-inclusive totals. Include malformed requests, slow Git and a two-thread/same-cwd fixture. Run tests and type checks in the base package, OpenCode integration and new Codex integration, and add the new package to CI. Keep provider dependencies out of the standalone statusline install. Validation on the real host should cover selection and updates in addition to fixtures. [Small protocol fixture suite][takumipr] · [Repo CI](../../.github/workflows/ci.yml) · [Root package](../../package.json) · [OpenCode package](../../integrations/opencode/package.json)

If an ANSI bridge becomes a separate deliverable, target the **existing cxstatusline patch's v1 contract** before considering ownership of a Codex fork. An explicit stdin adapter, a launcher targeting a compatible patched executable, and a compositor with a physical cap of three rows would be required. The current Koko CLI defaults unmarked input to Claude and the framed renderer can produce at least four rows for a header and one body row. The brandonwie hook would need its own one-line format and environment/file adapter. A tmux pane has room for the current panel but introduces a launcher, binding and cleanup lifecycle.
